# 01 — Codebase Cartography

Before you can change a system safely you need a map: what the deployables are, where ownership boundaries sit, and which flows carry the business. This module builds that map for Flagsmith and teaches the transferable skill of building one for any repo in your first week on a job — which is also a direct interview question ("how do you approach an unfamiliar codebase?").

Read in order:

1. [01-system-map.md](01-system-map.md) — the shape of the monorepo and its runtime surfaces
2. [02-file-reading-order.md](02-file-reading-order.md) — 30 files in the order that compounds understanding
3. [03-domain-glossary.md](03-domain-glossary.md) — the product nouns, with code locations
4. [04-runtime-and-tooling-map.md](04-runtime-and-tooling-map.md) — build/test/dev tooling and runtime boundaries
5. [05-key-flows.md](05-key-flows.md) — six end-to-end traces; the backbone the rest of the curriculum rotates through
